# Architecture

## Canonical world

The shared generator produces a 6144 × 6144-meter island, a 3073 × 3073 Float32 heightfield at two-meter spacing, and entities with stable IDs. `src/world/generator.mjs` is shared by the build script and a dedicated browser generation worker. Integer-seeded noise shapes a coarse landscape which is sampled into the full canonical field; priority-flood drainage supplies descending river routes. Site terraces, slope-aware connected roads, breakable architectural modules, scenery, and residents are generated afterward. Bounded deterministic retries retain the original seed identity. Every candidate must pass coastline, population, road connectivity, identity, budget, and grounded support validation before acceptance.

The build-time island is a reference asset for tests and benchmarks. Runtime players preview and select a generated candidate. IndexedDB stores the exact baseline separately from damage, and island replacement writes the baseline and deletes old damage in a single transaction. Reload loads the stored baseline rather than regenerating it under potentially changed rules. World version 8, save compatibility version 9, and generator revision 1 prevent component IDs or terrain sample edits being applied to another baseline. Preferences remain independent. Historical gameplay regression tests use a separately generated fixed version-7 fixture under `tests/fixtures/legacy-world`, which is excluded from production assets.

`WorldData.castles` identifies all fortress bounds, assemblies, centers, and landmarks; the original singular fields remain aliases for the grand castle for weapon and benchmark compatibility. Castle resident homes are mapped by assembly ownership rather than assuming every unclassified structure belongs to the main fortress. Tree species are baseline metadata looked up through stable source IDs for intact, moving, and settled rendering, preserving the packed body protocol.

A sparse immutable `RiverField` samples generated channel water elevations. Terrain `surfaceHeight` combines river surfaces, sea-level flooding, and laser exclusions. Water collision and weapon effects use that elevation. Initial readiness transfers a dense byte water mask rather than enumerating millions of ocean sample IDs; subsequent flood and dry deltas remain sparse. Ocean rendering extends beyond world bounds with explicit shader handling for out-of-range terrain UVs. River surfaces sample authoritative terrain and the shared wet mask, including saved laser exclusions.

The illustrated preview samples the completed candidate heightfield and its actual entities, roads, and rivers. Terminated generation workers and generation tokens reject stale results. Versioned seed codes and links select candidates without sharing damage or automatically overwriting local progress. Preview acceptance confirms replacement before committing. Storage-disabled sessions can replace their in-memory world through complete renderer/worker cleanup.

Terrain sections are 64 meters wide. Rendering chooses two-, four-, or eight-meter spacing with shared two-meter stitched boundaries and globally sampled normals. Physics uses exact two-meter triangles matching terrain sampling. Shared edge samples come from one global array; crater updates mark both adjacent sections dirty. Rapier heightfield colliders are maintained around the aircraft and moving debris, while flight/projectile terrain sweeps query the canonical heightfield everywhere.

The saved render-distance preference defaults to 1,200 m and is normalized to 600–3,000 m in 100 m steps. Terrain visibility includes a 64 m boundary margin, with a 100 m preload band and 500 m retention band. Terrain meshing runs in a dedicated worker; mesh installation and incremental ruin work share a render-frame deadline. Static structures use 256 m batches, trees use 512 m batches, and distance culling uses each batch's bounding sphere so nearby geometry is retained. Rubble, residents and monsters follow the selected distance; the camera far plane includes 256 m of headroom. Sky scaling keeps it inside that plane, and fog adapts to the horizon. Near-detail and shadow thresholds remain independent of this preference. The worker and world saves receive no render-distance setting.

The public worker command boundary and preference normalization pin destruction to `DEFAULT_DESTRUCTION` and Valley-scale nuke strength; only `noCooldown` is user-configurable. The internal profile helpers retain legacy values to restore already-launched saved strikes and support destruction regression tests. Rapid fire uses a 0.1-second cooldown for every weapon, with a small comparison tolerance for fixed-step floating-point accumulation.

## Simulation authority

The worker owns the aircraft, projectiles, destruction, Rapier world, and time. Commands are ordered worker messages. The fixed-step loop advances at 60 Hz. Each worker callback runs at most two ticks and yields after eight milliseconds of work; backlog is bounded to 100 ms. Routine snapshots publish at up to 30 Hz, while command/pause snapshots remain immediate. All moving projectiles have stable IDs for interpolation. The main thread buffers worker snapshots for 100 ms and advances a monotonic simulation playback clock using the browser animation-frame timestamp, interpolating aircraft positions, quaternion orientations, residents, and moving bodies on the same timeline. Duplicate command snapshots replace equal-time states without restarting interpolation; pause uses the latest state and respawn/reset clears the buffer. It follows with a spring camera, renders effects, and handles UI and audio.

Flight uses an arcade steering model, not an aerodynamic solver. Aircraft and projectiles use swept queries plus heightfield sampling. Physics bodies are reserved for substantial fragments; the aircraft and projectiles are analytically advanced.

Structures start with static box colliders. Build-time adjacency connects touching parts within each structural assembly. After an impact or foundation excavation, rooted graph traversal finds unsupported components. These components become spatially grouped rigid-body sections. This is a gameplay support model, not engineering-grade structural stress analysis.

Strong debris impacts can break further pieces. Trees use a trunk collider and a moving tree representation; branches and foliage effects are cosmetic. The default global active-body cap is 256, adjustable from 64 to 8,192. Capacity pressure demotes the oldest moving body to lightweight ballistic motion; excess direct-impact pieces also use ballistic motion, and unsupported structure groups retain priority through grouping. Demotion preserves identity, position, rotation, linear velocity, and angular velocity.

## Weapons and large destruction jobs

`WeaponId` includes cannon, nuke, and laser, while `ProjectileWeapon` remains cannon/nuke; `NukeYield` resolves a configured blast profile at release. Commands select the weapon and yield. Snapshots expose independent cooldowns and typed projectiles. Elongated projectile bodies use swept capsule queries matching their six- and eighteen-meter render scale.

Nukes enqueue serializable terrain, entity, and support phases. The worker schedules approximately two milliseconds of extra destruction work per tick, completing an atomic terrain section or connectivity traversal before yielding; unsupported clusters are queued and consumed incrementally. A single atomic unit may exceed that soft budget; diagnostics report its measured duration. Canonical samples are assigned to exactly one section job, and all adjacent render/collision sections refresh together.

Entity and ruin spatial indexes avoid repeated whole-world scans during broad blasts. Static rubble is rendered in 128-meter batches covering four terrain sections, rebuilt only when their content changes; moving debris remains a separate instanced layer. Smoke clouds use camera-facing instanced puffs, expire after about twenty seconds, and are capped at three.

## Persistence and bounded aftermath

Terrain changes are compacted by sample index, and structural removal is a set of IDs. Rubble is spatially compacted to 36 records per 64-meter section at the fixed Standard budget. Consolidation combines same-material records into rough piles with accumulated volume and collision proxies. Existing piles absorb further overflow so recognizable individual sections remain. Paused restoration uses the same compactor, rather than dropping saved moving pieces when a section is full.

A save stores a version, baseline world version/seed, revision, clock, edited samples, removed IDs, static rubble records, and pending destruction jobs. Edited terrain uses an interleaved Float32 buffer of exact sample indices and canonical heights; the worker transfers ownership of the new save buffer without cloning thousands of tuple objects. Version-5 saves support packed terrain arrays; older baseline versions require explicit recovery. The worker completes restored jobs before publishing its ready message. Active bodies are captured in packed poses without mutating live physics, then grounded and compacted during paused restoration. Reset invalidates pending save requests so an older write cannot resurrect the prior destroyed world.

IndexedDB transactions provide atomic replacement of the current save. Interrupted writes report failure and leave the game playable. The game does not promise a final asynchronous write during tab termination; periodic autosaves and saving on pause are the primary protection.

## Rendering and budgets

Scenery uses spatially grouped instancing; distant pines use simpler geometry. Terrain damage updates existing vertex and normal buffers in marked sections; topology is rebuilt only when detail level changes. Shadows are updated periodically and focus on nearby geometry. Water uses a reduced-resolution reflected scene, procedural ripples, a connected-water mask, and depth-dependent tint. Transient explosion effects are omitted from reflections.

The first release approximates underwater appearance with terrain-depth color rather than tracing refraction through a complete underwater scene. Shoreline appearance is approximate; the connected flood mask controls where water exists.

Particles are pooled. Large rubble has real collision, while small visual particles do not. Cosmetic randomness is intentionally independent of the authority's terrain and structural state.

## Future multiplayer boundary

A future server should validate input and own authoritative impacts, terrain revisions, structural removals, and major rubble. A late joiner receives the baseline identity and a current compact world snapshot, then ordered deltas. Clients may predict flight and display immediate effects, reconciling with server snapshots later.

Do not synchronize every dust particle or rely on multiple browsers independently reproducing rigid-body trajectories. The current Rapier worker can inform a future server implementation, but transport, reconciliation, room hosting, authentication, and anti-cheat remain future work. Static Cloudflare Pages hosting does not dictate the simulation server provider.

Control and rapid-fire preferences occupy a separate IndexedDB record. Reset clears only the current world. Baseline/save version 5 deliberately uses the existing incompatible-save recovery flow for older worlds.

## Flying wreckage

Blast profiles capture physical-body limits, launch speeds, and cosmetic-ejecta allocation. Prepared box partitions create two to six nonoverlapping physical pieces from a module. CCD is enabled for fast chunks. A canonical terrain sweep catches fast fragments crossing a streamed heightfield boundary; collision-tested movement remains consistent with edited ground. Both weapon classes shove existing moving wreckage and reactivate a spatially indexed selection of settled ruins. Nuke jobs store resolved profiles, excavation attenuation, deterministic seeds, and deferred support clusters so restoration does not drop unfinished damage.

`FragmentEffect` messages carry a seed, source position, blast origin, material, count, spread, and speed. The renderer starts with a 4,096-instance pool and grows only for actual configured limits with terrain-swept ballistic motion and damped bounces. These pieces use no Rapier bodies, do not alter authoritative collision, and are not saved. Smoke, cosmetic chunks, and flashes are omitted from water reflections. Default physical caps are 64 pieces per cannon impact / 128 per nuke within a global cap of 256; legacy/internal profile helpers support larger budgets for regression tests; chain collapses can contribute further bodies over subsequent ticks within that global cap.

Excess major wreckage starts at its source transform and advances in the worker with gravity, tumbling, canonical terrain sweeps, damped bounces, and map-boundary confinement. It becomes section-compacted static rubble only after resting on the current ground; there is no predicted landing teleport or airborne timeout settlement. This lightweight layer omits structure and mutual debris collisions, retains one representation per overflow source/group, participates in repeat blasts and laser cleanup, and shares packed body snapshots and save capture with Rapier bodies. Render instances grow as needed and interpolate position and quaternion orientation between snapshots. The performance display reports rigid and ballistic counts separately. Damage is independent of cosmetic quality. Craters have deterministic irregular contours and exposed soil/rock coloration; depth remains bounded by original terrain minus 25 meters.

## Experimental budgets and flight smoothing

`destruction-settings.ts` retains validated legacy profile mappings for save restoration and internal tests. Public preferences and worker commands fix future launches at Standard budgets, Valley-scale nukes, and the default laser profile. Saved projectiles and jobs retain their resolved profiles. Enabling No cooldown clears existing weapon timers and then fires at 0.1-second intervals while held, bypassing projectile and pending-job admission limits. Normal mode retains the usual timers and admission limits. Legacy noNukeCooldown preferences migrate to the all-weapon noCooldown setting.

Static fallback preserves source module dimensions at every tier. Rubble retention controls record detail; consolidation preserves material volume in approximate local piles. Lowering live-body limits demotes at most sixteen excess bodies per tick without snapping them to the ground. A collider-to-moving-body index avoids scanning every moving body for each contact. Cosmetic pool resizing trims inactive slots in place.

Aircraft use the shared `SnapshotTimeline` described above, with about 100 ms of presentation delay, rather than a second aircraft-only clock. Resume reseeds it from the latest snapshot and resets camera following; teleports and crash transitions also reset the timeline and camera. `flightPose` uses quaternion slerp and position interpolation on the selected simulation-time bracket. Camera aim has independent exponential smoothing, and the shake offset is applied after updating a stable unshaken camera position. Flight speeds, steering authority, boundary assistance and collision rules are unchanged.

`frame-stats.ts` derives median, p95, worst-frame time and 1% low FPS from the last 600 uncapped active-frame intervals. The 1% low uses the mean of the slowest ceiling(1% of sample count) durations and remains in warm-up below 100 samples. The collection restarts on resume, world reset, quality/distance changes, and performance-display toggles. It measures delivered frame cadence; it does not substitute for GPU timing or all-pass draw-call accounting.

## Final polish

`preferences.ts` normalizes persisted settings and applies preference revision 3. The earlier automatic-on eye default is disabled once, while later explicit choices persist. Migration replaces the old eight-monster default with 20 and retains earlier migrated nuke choices; new users get Valley-scale without changing saved terrain, structures, experimental sliders, or storage identifiers. Presentation branding is independent of the existing `lantern-vale` database name.

Camera modes are chase, cinematic, and photo. Cinematic changes framing only. Photo sends the existing pause command and waits for a `paused` message carrying the authoritative snapshot before enabling free-camera movement. Rendering remains active with effect time frozen. Escape and interruption paths clear input and return to paused chase. PNG capture renders synchronously before `toBlob`, without preserveDrawingBuffer.

Transient `contactSound` messages carry position, material, energy, and action. Worker-side spatial/time aggregation bounds sound traffic without altering collisions or damage; audio reuses noise buffers and caps voices. Cut-face texture atlases and geometry are shared by moving and settled fragment instances. Scar color generation is shared by terrain build and refresh paths to preserve identical section edges. Dust uses a fixed 256-instance pool.

## Orbital laser and deep excavation

Space Laser locks a freshly swept surface target along the jet's forward aim. The worker owns each four-second charge and five-second beam, plus its independent cooldown. Normal release sets a 24-second timer (nine seconds active plus fifteen seconds recharge); rapid fire starts a strike at 0.1-second intervals without shortening charge or beam duration.

The beam clears an expanding horizontal cylinder across the full vertical world column, reaching a 190-meter radius after one firing second. Structures and substantial debris are removed directly; vaporized source IDs suppress old deferred structure fragments. Outside wreckage from those sources remains valid. A separate support queue resolves surviving unsupported sections, and final cleanup removes debris inside the completed footprint.

Laser terrain jobs coalesce by 64-meter section and target, retaining the greatest requested progress. Absolute edits monotonically lower samples toward a steep, rim-tapered 500-meter shaft relative to baseline; duplicate/replayed work cannot deepen it further. Final strikes track their own outstanding sections, so continuing unrestricted fire does not prevent older strikes retiring. Work uses the shared soft destruction budget. Dry samples clear existing flood values and block subsequent flood traversal. Ordinary crater operations preserve already-deeper samples.

Version-5 saves include active strike ages/phases, per-section laser work, deferred support names, the independent laser cooldown, packed dry sample IDs, and vaporized component IDs. Queued edits complete before ready; unfinished live strike clocks remain frozen until play resumes. Restoration permits depths down to baseline minus 500 meters only in saved laser areas. The existing incompatible-save recovery dialog protects older baselines and preferences.

Rendering uses shared instanced cylinders, rings, impact discs, and a fixed electrical-arc buffer. The nearest eight strikes have detailed presentation; remaining strikes use a growing pool of simple columns. Four selected spatial audio voices share generated noise and the existing compressor/ceiling. Effects follow simulation time and reset/pause/photo behavior. Photo movement can descend into deep shafts. Substantial bodies use terrain-relative escape checks instead of an absolute negative-altitude cutoff.


## Configurable space laser

Destruction preferences normalize laser size (0–100, logarithmic 190–approximately 8,691 m radius), depth (25–500 m), and brightness (0.25–2). Launch captures a profile on each strike; physics, visuals, and saved work use that profile independently of later preference changes. Older version-5 profiles and work targets resolve to defaults without replacing the world.

Excavation targets carry radius/depth and coalesce only when center and both dimensions match. Work yields between terrain sections and between independent targets. For radii over 500 m, section work also performs static object and settled-rubble cleanup across all map sections, including fragments whose centers lie outside the footprint but whose dimensions intersect it. Moving debris and cosmetic chunks are cleared during the burn; newly settling fragments are suppressed by the active footprint. Final section acknowledgements retain each finishing strike until its cleanup completes.

## High-count debris performance

Body snapshots retain the in-process `BodyView[]` API for saves and tests. Worker snapshots instead contain one transferable `PackedBodies` buffer: 50 bytes per body, with signed integer identity/source, ten Float32 transform components, and byte material/kind tags. The main thread binds packed actors to reusable records and consumes packed body transforms directly, including pause/photo snapshots. Airborne transforms interpolate in the vertex and depth shaders; eye-enabled rendering retains CPU transforms. The worker never transfers a live physics buffer. Body IDs retain integer precision and transforms use submillimeter Float32 accuracy across the map.

The cosmetic pool stores live fragments contiguously in a preallocated Float32 buffer. Expiration and vaporization swap the last live slot into the removed slot; lowering the limit truncates the live prefix permanently. Burst work is capped by the pool's limit. Transform composition writes directly into the instance buffer; colors update only when pool membership changes. Paused, unchanged frames reuse buffers. Moving rigid-body instance capacity follows the largest physics setting, updates once per snapshot, and uploads only occupied ranges.

Physical updates reuse view transforms, avoid duplicate Rapier translation reads, cache size bounds, and settle sleeping bodies before other reads. Map insertion order gives constant-time oldest-body eviction. CCD starts enabled only for chunks fast enough to need it and is refreshed when existing wreckage is blasted. Terrain sections cache a conservative maximum including shared border samples; a segment above every intersected section's maximum skips the terrain sweep. Craters, laser excavation, and restoration only lower the baseline, so these bounds remain valid. Other segments retain their original canonical sweep and streamed Rapier collision.

Run `npm run benchmark:destruction` for separated airborne-body, transferable-snapshot, cosmetic-update, and actual castle-collapse CPU timings. It prints mean and p95 in milliseconds; it does not measure browser GPU cost or promise a frame rate. Defaults retain 256 active bodies and 4,096 cosmetic chunks. Extreme supports 8,192 bodies, 2,048 cannon / 4,096 nuke pieces per blast, and 65,536 cosmetic chunks. Above 512 active bodies, collision layers retain the 128 largest sections as major bodies. Other physical chunks collide with the world and major bodies, but omit mutual chip contacts. New large pieces fill available major slots. Full mutual collision is restored at 256 bodies, with hysteresis preventing repeated graph rebuilds. Collider removal, laser vaporization, and settlement maintain this budget. Default-sized explosions retain full contacts. Dense ground contact and shadow/reflection rendering remain workload-dependent.

The local CPU comparison on 2026-10-01 used the same generated world and requested body budgets, with the original simulation/cosmetic implementations as baseline. Mean/p95 timings were: 8,192 airborne bodies, 15.35/19.18 ms → 11.25/13.64 ms per step; their snapshot preparation/transfer, 27.14/29.51 ms → 1.41/1.66 ms (decode adds 0.14/0.23 ms); 16,384 cosmetic chunks over flat ground, 3.15/3.35 ms → 1.96/2.04 ms per update. The new pool updated 65,536 cosmetic chunks in 7.99/8.22 ms. The 4,096-body castle collapse averaged 39.86/52.76 ms → 28.38/44.15 ms, ending with 5,167 vs 5,986 moving pieces because collision scaling changes subsequent contact cascades. These are single local runs, not browser frame-rate guarantees; dense collapses still exceed a 16.7 ms simulation budget.


## Continuous overflow debris

The ballistic update benchmark added on 2026-10-01 measured airborne batches at 4,096 pieces: mean 0.58 ms / p95 0.90 ms, and 16,384 pieces: mean 2.14 ms / p95 3.13 ms. These isolated worker CPU timings exclude rendering, snapshots, rubble insertion, and dense terrain contacts. The browser verification of a default Valley-scale castle blast showed 3,906 ballistic pieces plus 152 rigid bodies at 0.75 simulation seconds, and 3,486 ballistic pieces plus 178 rigid bodies at 1.75 seconds. Counts change as debris lands and contact cascades break surviving structures. Save capture records airborne poses; paused restoration converts them into ground-level rubble without changing live motion during capture.


## Roof silhouettes and distant flash

Debris gravity is shared by Rapier bodies, worker ballistic wreckage, and cosmetic chips at 21.6 m/s² (20% above the earlier 18). Weapon projectile gravity is unchanged. Roof and slate sections fracture into four closed tetrahedral wedges that exactly partition the intact pointed roof. Each wedge retains its original sloped exterior and has two exposed cut faces. Moving and settled colliders share the same vertices as rendering, and lightweight landing and save capture use each rotated wedge's lowest corner. Roof wedges remain independent through support collapse, physics budget overflow, settlement, reblasting and save restoration. Four cached geometries are instanced by material and shape. The optional `roofPart` tag occupies spare bits in the kind byte, keeping packed body buffers at 50 bytes and old saves compatible. Rubble consolidation retains actual pyramid/wedge volume and clears the individual shape tag when creating a pile.

Nuke exposure reaches 2,200–6,000 meters according to yield/scale, giving a visible atmospheric wash across the whole valley even when the blast is behind the camera. Looking toward the blast remains brighter. Pulse durations, strongest-only overlapping contributions, pause/reset behavior, and the reduced-effects opacity cap and short fade remain unchanged.


## Expanded terrain and civilian simulation (version 7)

Map section indices derive from the shared 96-section row width, independently of the 32 samples per 64 m section. Water textures and save validation use the 3,073-sample terrain row stride. TerrainView allocates section records up front, builds coarse geometry near spawn, then loads/refines at most eight sections per render frame and discards meshes beyond 2,100 m. Height edits survive unloads, so subsequent builds include craters and dry laser shafts. Physical terrain continues streaming around aircraft and activity.

Civilian spawn metadata identifies stable IDs, home assemblies, and settlement IDs. The worker owns movement, casualties, settlement timers, and structural-loss counts. Resident spatial cells bound swept aircraft/wreckage queries; residents do not add Rapier bodies. Structure removal updates mourning and overlap hazards, and both rigid and ballistic wreckage sweep expanded boxes against nearby residents. Monster damage compares the active population before and after the batch to identify local clears and final victory. Population settings rebaseline threats without emitting celebrations. Reaction events are coalesced per settlement until the end of the frame; sadness cancels simultaneous cheering.

CivilianState and SettlementState accompany simulation snapshots and saves. Shared instanced body parts animate from snapshot phase, with no independent wall-clock animation during pause/photo. Generated spatial voice chords use the existing mixer, volume, voice budget, and reset/pause lifecycle. Version-7 world/save compatibility prevents old sample indices and structural IDs from being interpreted against the expanded map; preferences remain independently compatible.

Terrain rendering merges editable 64-meter sections into 256-meter draw tiles. Section rebuilds and tile merges have per-frame count and time budgets; authoritative height data remains available while meshes stream. Water reflection and shadow updates use separate elapsed-time deadlines. Terrain and water textures upload packed dirty-section rectangles after edits; resets and context recovery upload the full field. Distant monsters use four shared instance batches. Civilian threat detection uses a 192-meter spatial index. Population summaries are computed in the worker and shown in the flight HUD. Added residents keep the original spawn IDs stable so version-7 casualties still restore.


## Performance release (save compatibility 9)

The generator and exact world baseline remain at revisions 1 and 8. Terrain journals and paged dry-index bitsets accumulate changes as they happen; autosave does not enumerate the 9.4-million-cell heightfield or dry mask. Save capture rotates journals and yields while packing changed sections. Journals remain until a committed-capture acknowledgement. Global actor/runtime metadata, section terrain/dry buffers, and ruin changes commit atomically. A failed synchronous clone explicitly aborts the transaction. Valid version-8 saves migrate atomically, with the original retained on failure. Older incompatible saves retain recovery protection. Preferences and baseline replacement remain separate from ordinary damage captures.

Terrain jobs carry island epoch, section revision, requested LOD, and a two-sample halo. Results with obsolete identity, edits, or detail are discarded. The worker caches up to 2,048 section geometries; the renderer retains up to 160 tiles. A masked coarse surface remains while detailed tiles stream. Spatial working sets and LOD hysteresis avoid scanning and sorting all sections during ordinary flight. Canonical two-meter collision data remains independent of visual LOD. Height and water uploads use bounded section staging buffers and the pinned Three.js r180 texture-binding cache; they do not query GL state synchronously. Mesh installation and uploads share the optional frame deadline.

Static batches freeze transforms and leave the active scene outside their working set. Removal swaps the last surviving instance into each deleted slot and repairs stable-ID mappings. Species share trunk batches, with distinct crowns. River reaches and corner pools merge into 256-meter spatial meshes; their original vertices, elevations, and wet/dry shaders remain intact. Near monsters use instanced animated body parts, distant residents use single proxy instances, and ordinary pineapple projectiles use body/crown instancing. Eye-enabled projectiles retain individual anchors. Disabled eyes create no anchors and run no update traversal. Enabled eyes cache source membership and bounds.

Auto starts at 900p, reacts after 450 ms of continuous pressure, and requires 15 seconds of headroom before recovering. It considers render preparation/submission, GPU queries where supported, simulation cost, snapshot lag, and delivered cadence. Resolution ranges from 720p to 1080p; manual resolution is preserved. The requested view distance remains unchanged. Four nearby point lights provide lantern illumination. Loading prewarms both the screen and actual water-reflection shader variants. Island disposal releases reflection and shadow render targets and textures held in shader uniforms. Cosmetic flashes, clouds, chips, and overlapping sounds use bounded pools and merging; authoritative strikes remain independent.

Runtime static colliders stream around aircraft, moving bodies, and contact regions. Global shape queries still test exact offscreen source/ruin shapes. Terrain collider rebuilds coalesce by section and run through a bounded queue; canonical sweeps remain available while colliders rebuild. Support searches, falling-component grouping, and collapse emission use resumable phases. Nearby combat, weapons, aircraft, and collision stay at 60 Hz. Background navigation uses distance tiers and immediate threat activation. Residents cache ground and water queries by terrain-section revision; excavation and flooding invalidate affected sections. Static navigation candidates use 16-meter resident cells and 64-meter monster cells; exact horizontal and vertical clearance and authoritative removal IDs determine obstruction.

Motion packets carry island epoch and pool-slot ownership. Eight reusable buffers bound packet storage. Replaceable poses coalesce when no slot is free, while ordered gameplay events remain independent. Timeline retirement returns buffers after their final render use. Pause/reset/island replacement retire obsolete packets; the interpolation delay remains unchanged.

Simulation maintains a dense pose cache as rigid and ballistic debris move. Membership deletion swaps the last slot and repairs the ID mapping; physics maps retain their original iteration order. Packet/save packing copies contiguous arrays into the existing 50-byte body ABI. Source IDs, material and roof tags remain stable. Packet storage never aliases the simulation cache.

Ordinary autosaves use a one-shot MessageChannel from simulation to the dedicated storage worker. Terrain buffers, dry masks, ruins and actor metadata bypass the render thread. The UI receives only capture/revision/hour, bounded slice measurements and a committed transaction receipt. The storage worker rejects waiting channels and aborts active writes before acknowledging retirement. Transfer preparation is timed in the simulation worker and included with capture slices. Explicit debug snapshots and migration retain the copy-preserving write interface. Fatal errors retire capture ownership and close the writer.

Auto ignores deliberately paused cadence. Resuming clears accumulated overload/headroom and frame/CPU averages while retaining the selected quality level. CPU pressure includes the complete render preparation and submission once per frame.

Save capture ownership is independent of island epochs. Reset and replacement retire pending requests; an old task's completion cannot clear a newer task's state or acknowledge a different island's journals. Context recovery drops invalid GPU queries, reacquires extension support, and prewarms while paused. Warmup has one owner and cancels program polling when the context is lost or its renderer is disposed.

Ordinary damage commits run in a dedicated storage worker. The client transfers independent contiguous terrain/dry/pose buffers and waits for the committed reply before acknowledging the simulation journals. Baseline replacement and damage reset first await worker retirement; retirement invalidates yielded preparation and aborts active transactions. Baseline validation, recovery reads and preferences stay on the explicit main-thread storage interface. Worker failure rejects pending commits and preserves the previously committed save.

Rubble broad-phase terrain bounds use immutable 64-meter section ceilings, then revision-cached 16-meter ceilings from current terrain. Shared samples and neighbor invalidation keep those bounds conservative after craters, shafts, restore and reset. Visible rubble consumes packed tags and scalar positions before reading transforms; roof variants use cached keys instead of per-piece strings.

`performance.html` is a production entry point with an isolated test database, six foreground 30-second cases, a 15-minute mixed-combat soak, storage fault checks, and manual seed/view/night/eyes/distance inspection. Frame statistics cover the entire case; simulation samples include every tick. Stage statistics use a bounded rolling ring (4,096 render samples), so soak stage percentiles describe its tail rather than the full 15 minutes. GPU timing uses asynchronous disjoint timer queries, without synchronous readbacks. Browser memory values, when exposed, and resource/queue samples provide bounded-growth evidence. CPU benchmarks establish CPU costs, not hardware FPS guarantees. See `docs/PERFORMANCE_QA.md` for measured gates and outstanding work.
